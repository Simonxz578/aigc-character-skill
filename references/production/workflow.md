# 人物视频生产路由

## 沿用项目

先读取已有brief、project.md、timeline、参考与最近用户修订。若只修声或合成，不重开分镜。将明确制作、文件写入、生成提交的范围分开；用户要亲自点生成时完成画布配置并交就绪证据。

## 从创意到素材

建立production brief：受众、目标、时长/画幅、角色母版、关系、台词语言、配音、主音轨、字幕、禁止改动、工具范围。未指定的新短片可用1080×1920/30fps；现有视频局部修复保持源规格，显式用户规格优先。

role_map为每份参考说明identity / action / camera / environment / audio等作用及排除项。舞蹈参考只给动作/运镜时，不借脸与服装。逐镜头写opening_state、playable_event、ending_state、duration_frames、screen_direction、prop_owner；交互必须有承重/接触/松手顺序。

生成前核实平台和模型，记录native输出。真正人物连续动画先做4–6秒动作样本，验收实际连续帧、身份、方向、变脸、手与道具；静态zoom/pan不能让此门槛通过。已有合格镜头或用户要求直接后期时不重做pilot。

每段取回后probe、保存hash并回写实际首尾状态。通过部分镜头时只重试错误镜头；重试次数和成本沿用用户预算，默认最多两次局部修订后报告具体失败。用户允许混剪时可采用局部细节切换、景别匹配或animatic，交付名称如实说明。

## 后期与交付

按音轨策略定声音，再按真实唱词/台词定字幕；片头叠在时间槽内。选择FFmpeg、HyperFrames或Remotion中的必要运行时，已有工程优先保留。以 [声音与后期](audio-finishing.md) 做编码和QA。

阶段状态与感知状态分开。保存源文件、字幕、PCM、生成回执、技术probe/全解码/编码帧截图；用户未要求源码打包时直接交可播放MP4和必要字幕链接。技术问题尽量自己解决，只有身份来源、必须取得的素材或外部提交权限真实缺失才询问。
