# 自查与验收

内部评分 1–5；4 表示可用且没有具体未解决缺陷，5 表示该场景控制充分。任一项 <4，定位该问题并改一次；仍不可满足就简短说明实际冲突。分数不预测生成模型成功率。

| 项目 | 4 分标准 | 具体修订 |
|---|---|---|
| 可演性 | 每段 2–4 主次动作、能在时长内完成 | 删除同时发生的多余动作，留收势 |
| 情绪因果 | 变化来自事件/判断/选择 | 补一条可感知的新信息 |
| 微表情精度 | 看得见且不含伪生理 | 换成视线、唇线或呼吸动作 |
| 角色连续性 | 身份、服装、手和道具归属稳定 | 锁定锚点、明确交接顺序 |
| 摄影 / 物理 | 镜头、支点、声音、接触合理 | 去掉矛盾运镜，保留接触点 |
| 中文质量 | 自然连贯，无重复凑字 | 去掉抽象词，合并禁令 |

## 负面约束

只写当前高风险项，如“保持左右位置与持剑手；不得自动加泪水或字幕”。不复制几十条无关的“无…”。“眼里有泪但不掉”不是矛盾；“完全无声”与“可听见门响”才是矛盾。否定镜头推进不等于积极要求推进。

## 静态验证器的边界

`scripts/validate_prompt.py`：字符数包含所有 Unicode 码点和换行；检查时间区间、粗略对白长度、重复限制、部分词面冲突和交接提示。warnings 为审稿线索，非错误退出；不会判断真实参考相似度、真正动作质量、事实准确性或全部自然语言语义。画面不按提示词执行时，需要另行看实际视频。

回归用例与可观察预期见 [tests/forward_cases.md](../tests/forward_cases.md)。自动测试只验证脚本及示例结构；自然语言试用单列，不能把单元测试说成模型行为证明。
